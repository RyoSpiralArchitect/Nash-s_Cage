2026-09-04 / 入力契約案 0.1。国は日本を暫定選択。

## 結論

最初に再現するのは地球全体ではなく、**出典まで戻れる発電の排出会計**である。
その上に、石炭から既存LNG火力への小さな出力置換を「比較候補」として置く。
年次会計が再現できても、置換の因果効果や実行可能性が確認できたことにはしない。
LNGへの転換を政策として推奨する文書でもない。

楽観・悲観の方向に数値を寄せず、公表値、計算値、仮定、未同定を分離する。
不明な効果や供給余力を、都合のよい確率分布で埋めない。

## 1. パリ協定と発電量を直接つながない

| 層 | 入れるもの | ここから直接は導けないもの |
|---|---|---|
| 国際・国内の目標 | パリ協定、提出版を固定した日本NDC、国内計画 | 個別発電所のCO₂上限、制御権限 |
| 排出会計 | 燃料投入、発電量、係数、国内排出インベントリ | 何もしなかった場合との差 |
| 作用と資源 | 指定機・指定時刻の限界応答、追加供給余力 | 国家全体の政策効果、気候被害・死亡への因果 |

パリ協定の温度目標と各国NDCの仕組みは
[UNFCCCの説明](https://unfccc.int/process-and-meetings/the-paris-agreement)および
[NDCの位置づけ](https://unfccc.int/process-and-meetings/the-paris-agreement/nationally-determined-contributions-ndcs)
に基づく。発電部門への数値配分は、これらから自動的には決まらない。

日本の2025-02-18提出NDCは、2013年度比で2035年度60%、2040年度73%削減を目指す。
対象は全分野・複数GHG・LULUCFであり、発電の化石燃料由来CO₂だけではない。
単年目標であって、本契約の年間・累積CO₂予算を自動的に与えるものでもない。
基準年値は再計算により更新可能と記載されている。
原典は[環境省NDC](https://www.env.go.jp/earth/earth/ondanka/ndc.html)、
[提出本文の表1〜3・5](https://www.env.go.jp/content/000291804.pdf)。

従って `ndc_target` は目標のメタデータとして保持する。
`power_sector_budget_tco2`、`cumulative_budget_tco2` は、配分根拠がない間は UNKNOWN。
国の削減率を一律に各燃料・各発電所へ掛けない。国内計画上の部門目安を使う場合も、
[地球温暖化対策計画](https://www.env.go.jp/earth/ondanka/keikaku/250218.html)
との分類・電力配分前後の対応を別途確認する。

2026 NID表3-16（本文3-26ページ）では、`1.A.1.a 発電・熱供給` は、

### 係数の最小照合

[NID第3章時系列原本](https://www.nies.go.jp/gio/archive/nirdata/qu9bd600001b3pi9-att/L5-NID-Ch3-Energy-2026_web.xlsx)
の `CEF` シートはt-C/TJ・高位発熱量（HHV）基準。2024年度列はAR。

| 燃料コード | 原表セル | 炭素係数 [t-C/TJ-HHV] |
|---|---|---:|
| `$0123` 発電用輸入一般炭 | `CEF!AR12` | 24.75918569549864 |
| `$0510` 輸入天然ガス（LNG） | `CEF!AR57` | 13.840090612572233 |

例えばLNGの **1 TJ-HHVに対応する炭素を全量CO₂に換算する**と、
`1 × 13.840090612572233 × 44 / 12 = 50.74699891276486 t-CO₂`。
これは係数と単位の算定例であり、同じ電力供給を維持して50.747t減らせるとの実証ではない。
上の天然ガス総投入PJへこのLNG係数を無条件に掛けず、原燃料コードを照合してから使う。

## 3. 一対象・一作用・一資源

日本全体は会計の入口であり、運転操作の対象はさらに限定する。

| 項目 | 初回契約案 |
|---|---|
| 一対象 | 日本の一供給区域にある、指定した既存の石炭発電機。区域・発電機IDは未選定 |
| 一作用 | 指定時間窓で石炭機の送電端電力量を1 MWh減らし、指定既存LNG機で電力サービスを補完する比較 |
| 一資源 | 同じ時間・供給範囲へ届けられる、LNG側の追加送電可能電力量 `R_t` [MWh] |
| 一観測系列 | 対象機の同期した燃料投入から再計算する、化石燃焼CO₂ [t-CO₂/時間窓] |
| 第一出力 | 対象機・代替機の直接排出差。系統全体の排出差は別出力 |

`1 MWh` は作用量の設計値であり、観測された資源量でも推奨運転量でもない。
同じ時間・区域でも系統損失が変わるなら、代替側1 MWhだけで同じサービスになるとは限らない。
最初の作用例は「同じ受渡点で損失差なし」に条件づけ、これが確認できなければ未承認とする。

`R_t` は時間付きの供給能力であって貯蔵在庫ではない。未使用分を翌時間へ繰り越さない。
設備MW、年間MWh、LNG輸入トン数、過去最大出力をそのまま `R_t` に代入しない。
燃料在庫、停止状態、最低出力、起動時間、増減速度、他の供給約束、送電制約、予備力を
確認した追加供給余力が必要。予測値と実績値を分け、情報が利用可能になった時刻も残す。
石炭側にも、無作用経路に対して実際に減出力できる余地が必要である。
基準出力、最低出力、停止制約、増減速度に照らし、削減要求がその余地を越えないことを確認する。
時間窓の合計1 MWhが一致するだけでは足りない。制御刻みと両機の出力プロファイルを指定し、
各刻みで同じ電力サービスを維持する。送電サービス差が未評価なら受入しない。

「一資源」は明示する主資源を絞る設計であり、資金・燃料・系統の制約を無限と置く意味ではない。
それらの裏付けがなければ `R_t` 自体を UNKNOWN とし、総合的な実行可能性は主張しない。
初回はCHP、混焼、CCS付き設備を作用対象から除外する。除外に合う設備の実在確認も必要。

## 4. 入力の必須型

数値は `{value, unit, evidence_kind, source_id, locator, missing_reason}` を持つ。
`evidence_kind` は `reported` / `derived` / `assumed` / `unknown`。
政府統計の推計値を、独立した煙突実測に読み替えない。
UNKNOWNは数値の `null` と理由で保持し、ゼロ・補間値・任意分布へ暗黙変換しない。

| 入力群 | 必須項目・検証 |
|---|---|
| 出典 | 発行者、原本URL、公開/改訂日、取得時刻、原本SHA-256、表/シート/セル、変換履歴 |
| 時間 | 暦年/年度、開始・終了（終端の包含規則）、時間帯、観測時刻、利用可能時刻 |
| 母集団 | 国、供給区域、発電機ID、事業用/自家用、電気のみ/CHP、対象設備集合の対応表 |
| 燃料 | 原表燃料コード、標準化コード、物量単位、混焼内訳、化石/生物由来 |
| 燃料投入 | 消費量（購入量・輸入量とは別）、GJへの換算係数、HHV/GCVまたはLHV/NCV |
| 電力 | MWh、発電端/送電端/使用端、所内消費、揚水・蓄電の入出力、損失の扱い |
| 排出係数 | kg-C/GJかkg-CO₂/GJか、熱量基準、適用年・燃料、酸化率内包の有無、出典 |
| 排出範囲 | 化石燃焼CO₂、生物由来CO₂別記、直接排出/ライフサイクル、回収量の扱い |
| 資源 | `R_t`、算定根拠、有効時間・区域、既約定分、制約、残り余力の二重使用防止 |
| 効果 | 限界燃料応答、無作用経路、石炭側減出力余地、刻み別出力プロファイル、評価窓、起動停止・他設備・後刻反動の扱い、識別根拠 |
| 不確実性 | 測定誤差、統計改訂、推計誤差、感度仮定、構造的不明を別欄で保持 |

エネルギーバランスの変換投入は負号で表される場合がある。原表の符号を保存し、
投入の意味を確認した行だけを正の消費量へ変換する。全負値を一括で絶対値化しない。
秘匿・非該当・未推計・他区分に含む等の記号も元の意味を保存する。

## 5. 計算してよい量／まだ計算してはいけない量

### 会計

係数が `kg-CO₂/GJ`、燃料投入が同じ熱量基準の `GJ` なら、

`E_f [t-CO₂] = H_f [GJ] × EF_f [kg-CO₂/GJ] / 1000`

係数が炭素質量なら `44/12` の変換が必要だが、CO₂係数に重ねて掛けない。
酸化率も内包済みの係数へ二重適用しない。IPCCのTier 1既定係数は酸化率を内包する。
[IPCC 2006 Vol.2 Ch.2、式2.1・方法論](https://www.ipcc-nggip.iges.or.jp/public/2006gl/pdf/2_Volume2/V2_2_Ch2_Stationary_Combustion.pdf)

期間・設備範囲・電力端が一致し、`Q_f > 0` の場合だけ `I_f = E_f / Q_f` を出す。
これは平均原単位であり、限界削減効果ではない。HHVとLHVを係数付き換算なしに混ぜない。

### 作用

求めたい量は `A = E(無作用の運転経路) - E(指定作用の運転経路)`。
正なら削減、負なら増加。両経路の同じ電力サービス・評価時間窓が必要である。
`1 MWh × (石炭平均原単位 - LNG平均原単位)` は、平均を限界と仮定した感度計算にすぎない。
結果を出す場合は `CONDITIONAL_SCENARIO_ONLY` とし、実際の回避排出量と呼ばない。

限界応答を認めるには、同期した設備データと運転状態に加え、比較を識別する根拠が必要。
運転試験、妥当性を吟味した準実験、または校正・外部検証した運用モデルを区別する。
運用モデルでの推計は、検証後もモデル条件付き効果である。
単純なパリ協定前後の比較や年次回帰から「協定が減らした」とは言わない。

年間平均では需要・天候・停止・原子力再稼働・価格等の変化が混ざる。
電力系統の他設備、融通、蓄電、起動停止、後刻の増発も不変とは仮定しない。
年次を細かい疑似時系列に分割しても独立観測数は増えない。

IPCCは汎用の発電kWh当たり係数を与えておらず、燃料投入からの算定を基本にしている。
バイオマスのエネルギー部門での別記も、炭素中立の証明ではない。
[IPCC FAQ Q2-3〜5・Q2-10](https://www.ipcc-nggip.iges.or.jp/faq/faq.html)
LNG上流のCH₄や建設時排出を除いた直接CO₂比較から、気候影響全体の優劣を結論しない。

## 7. 次の実装とFurnaceの用途

順序は **原表固定 → 会計の再計算 → 不一致の説明 → 作用・資源の同定 → 限定した比較**。

1. 取得済みの2024年度エネルギーバランス表から、まず事業用発電の石炭・天然ガスの原表行を照合する。
   天然ガス/LNG、事業用/自家用、発電端/送電端の対応が閉じなければ結合を停止する。
2. 元の単位・欠測記号を残した取込器と、上記の型を検証する受入器を作る。
   CO₂再計算は排出源側で行い、電力消費側への配分済み排出と二重計上しない。
3. 一致しなかった行を全件保存する。丸め幅は原表精度から定め、後から許容差を広げない。
4. 次の壊れ方を先に固定する：年度/暦年混合、版混合、HHV/LHV混合、C/CO₂二重変換、
   発電端/使用端混合、CHP混入、混焼を単一燃料扱い、秘匿をゼロ扱い、平均を限界扱い、
   資源欠測、容量MWをMWh扱い、時刻を越える余力の繰越、石炭側削減余地不足、
   窓合計だけ一致して刻み別供給が欠ける場合、入力の未来情報漏洩。
5. 原表再現後に、独立データの有無と共通出典への依存を記録して検証計画を固定する。
   原表を作った同じ係数での再現誤差だけを、将来の予測誤差としない。

2026-09-04のFurnace稼働確認では、RTX 5090（約32GB）のGPU利用率は0%、
GPU計算プロセスは表示なし。利用可能メモリ約85GiB。一方CPUには既存処理があり、
占有してよいという意味ではない。今回は状態確認のみで、ファイル転送・大量計算は行っていない。

原表が固定できたら、隔離した作業領域で小さなCPU再現実行を行い、
ローカルとの同一入力・同一出力比較、時間・メモリ計測を先にする。
その後の大量実行候補は、受入拒否テスト、宣言した係数・改訂差・感度範囲の走査、
識別根拠を持つ時間ブロックの再標本化。独立性のない年次セルを大量複製しない。
未知の構造を恣意的な乱数で埋めた計算は、探索シナリオとして別集計する。

実行数、失敗数、UNKNOWN数、採用/不採用理由、計画・入力・コードのハッシュ、
実行環境、時間、再現結果を残す。GPU化は同じ計算の一致と所要時間を測ってから判断する。
大量実行しても `ACTION_EFFECT_UNIDENTIFIED` は解消しない。
